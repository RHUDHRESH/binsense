# The codebase, step by step

Three kinds of things live in this repo. Keep them apart in your head:

| Kind | Folder | Rule of thumb |
|---|---|---|
| **Core** | `pi_bundle/` | What runs on the Raspberry Pi. If it is not here, the demo does not need it. |
| **Model preparation** | `laptop/`, `colab/`, `labels/`, `artifacts/` | Run once on a laptop or cloud GPU to make the files the core uses. |
| **Experiments and evidence** | `experiments/`, `results/`, `docs/` | How we found out what works. Nothing in the demo depends on it. |

---

## 1. Core: `pi_bundle/`

Copy this one folder to the Pi and everything runs.

### The engine (one file)

| File | What it does |
|---|---|
| `binsense.py` | The whole decision engine. `BinSense` loads one `.pte` and one label pack, turns a photo into a tensor (`preprocess`), runs the model (`embed`), and turns the result into label probabilities (`choice_from`), tags (`multi_from`), yes/no answers and scores. `Cascade` chains a fast model and a careful model. |

### Ways to run it

| File | Use |
|---|---|
| `ui_server.py` + `ui.html` + `live.html` | The web UI. `ui.html` is the photo page, `live.html` is the webcam page. Start with `start_ui.bat` (Windows) or `start_ui.sh` (Pi). |
| `show.py` | One command that walks through the whole proof in the terminal. |
| `demo.py` | Offline check, model list, classification loop, hardware line, summary. |
| `trace.py` | One photo, every step printed: input, tensor, each model's scores and probabilities, decision. |
| `live.py` | Webcam in the terminal. |
| `run_eval.py` | The hackathon deliverable: prediction per image, results table, accuracy, timing, size, memory. |
| `service.py` + `binsense.service` | Folder-watching sorter with audit log, "not sure" folder and bad-file handling; the unit file starts it at boot. |

### Setup and measurement on the Pi

| File | Use |
|---|---|
| `setup_pi.sh` | Creates the Python environment and installs the libraries. |
| `build_executorch.sh` | Compiles ExecuTorch on the Pi. Needed on a Pi 4: the ready-made package crashes on its processor. |
| `tune_pi.sh` | Holds the CPU at full speed and stops background services. |
| `bench_pi.sh` + `summarize.py` | Every model at 1 to 4 threads with a temperature log, then one summary table. |
| `run_demo.sh` | Runs `demo.py` inside the environment. |

### Data the core needs

| Folder | Contents |
|---|---|
| `models/` | The `.pte` files: the models themselves (operations + trained weights). |
| `packs/` | Label packs (`.npz`): label names, the numbers that represent each label, tag groups, and how to prepare a photo for that model. A few KB each. |
| `images/` | 30 sample photos from TrashNet. |
| `organiser/` | The organisers' 10 photos (kept out of GitHub) and `labels.csv` with their true labels. |

### `pi_bundle/tools/`: one-off helpers, not part of the demo

| File | Why it exists |
|---|---|
| `bootstrap.sh`, `firstboot.sh` | Install BinSense on a fresh Pi from GitHub, by hand or automatically at first boot. |
| `provision_tools.sh` | Installs hardware inspection tools and prints a board report. |
| `eager_baseline.py` | Times the same model in plain PyTorch, for the comparison table. |
| `diag_sigill.sh`, `try_versions.sh` | How we found that prebuilt ExecuTorch crashes on the Pi 4, and that no released version avoids it. |
| `fallback_setup.sh` | A plain-PyTorch stand-in we set up while ExecuTorch was compiling. Not used in the demo. |

## 2. Model preparation

### `laptop/`: turning a PyTorch model into files the core can use

| Step | File | Output |
|---|---|---|
| 1 | `fetch_trashnet.py` | Downloads TrashNet and splits it: 240 test photos, 2,287 for everything else. |
| 2 | `export_tower.py` | Apple's MobileCLIP2-S0 image model as a `.pte` (ExecuTorch + XNNPACK), plus a spec file describing its input. |
| 2b | `export_gate.py`, `export_portable.py` | A small MobileNet as a `.pte`; and the same model without XNNPACK, as the slow baseline. |
| 3 | `build_labels.py` | A label pack from a labels file in `labels/` (runs the text half of the model once). |
| 4 | `fit_head.py` | Optional: fits a small decision table on top of the frozen model and adds it to a pack. |
| 5 | `add_groups.py` | Optional: adds tag groups such as "recyclable" to a pack. |

`laptop/deploy/` holds the scripts that copy the bundle to the Pi and start the install over SSH.

### `colab/`: training on a cloud GPU

| File | What it does |
|---|---|
| `train_waste_models.ipynb` | Fine-tunes MobileNetV2 and MobileCLIP2-S0 on TrashNet and exports both to `.pte`. Generated by `make_notebook.py`. |
| `students.py`, `students_a100.ipynb` | Distils the fine-tuned model into six smaller, faster MobileNetV2 students. Generated by `make_notebook2.py`. |
| `binsense_models/`, `students/` | What those runs produced: `.pte` files, their packs and result files. |

### `labels/` and `artifacts/`

- `labels/*.json`: human-written label definitions, the input to `build_labels.py`. `organiser_v1.json` is the set used for the organisers' photos.
- `artifacts/`: outputs of the export step on the laptop: spec files and packs. The large `.pte` copies here are not in GitHub; the ones the demo uses are in `pi_bundle/models/`.

## 3. Experiments and evidence

### `experiments/`: each folder is one question, with its own log

| Folder | Question | Answer |
|---|---|---|
| `accuracy/` | Can a stronger top layer, zooming, or saying "not sure" beat 92.9%? | 94.6% with a stronger layer; 98.6% on the 92% of photos it answers when allowed to abstain. |
| `cnn/` | Are small ready-made CNNs good enough? | No. Best was 89.2%. |
| `foundation/` | Are bigger models worth it? | No. Same accuracy, 2 to 4 times slower. |
| `own_model/` | Can we train on the laptop? | Not while other jobs were running; moved to the cloud. |
| `semicon_tricks/` | Do two ideas from chip-image matching carry over? | A margin-based confidence score helps a little; lighting normalisation hurts. |
| `data/` | What other waste photo sets exist? | Five downloaded, with licences and a category map. |

### `results/`

Every measured table as Markdown, CSV and JSON. File names say what was run, for example `results_laptop_own_mobileclip2_s0_256_fp32.json`. Everything here so far was measured on a laptop.

### `docs/`

| File | What |
|---|---|
| `CODEBASE.md` | This file. |
| `LEARN.md` | The ideas in plain language. |
| `PITCH.md` | The two-minute pitch and likely judge questions. |
| `make_charts.py`, `make_diagram.py` | Redraw every chart and the pipeline diagram in `docs/img/` from the result files. |
| `img/data_points.json` | Every number behind the charts. |

## How the pieces connect

```
labels/*.json ──► laptop/build_labels.py ──► pi_bundle/packs/*.npz ─┐
                                                                    ├─► pi_bundle/binsense.py ──► answer
PyTorch model ──► laptop/export_*.py or colab/ ──► pi_bundle/models/*.pte ─┘        ▲
                                                                                 photo
```

## Not in GitHub, on purpose

- `data/`: downloaded photo sets (about 500 MB).
- `.venv/`: the laptop's Python environment.
- `pi_bundle/organiser/*.png`: the organisers' photos, whose licence we do not know.
- Rejected or duplicate model files, caches and run logs.
